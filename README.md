# FPF 数据处理工具

读取 xlsx → 清洗处理 → 导出 R 可直接读取的文件,打包为单个 Windows exe。

界面分页签:**母猪综合查询**、**猪只转移**、**母猪档案**、**品种品系判定**。

## 一、打包 exe(二选一)

**本机打包**:安装 64 位 Python 3.10–3.15(python.org 官方安装包,勾选 *Add to PATH*),双击 `build_exe.bat`,
完成后得到 `dist\FPF数据处理.exe`。这个 exe 拷到别的电脑上不需要装 Python 也能运行。
exe 大小约 40 MB。

安装依赖时依次尝试清华、阿里云、腾讯云和官方源,某个源出问题会自动换下一个。

**GitHub 自动打包**:把整个文件夹推到 GitHub 仓库,在 *Actions → build-exe → Run workflow*,
几分钟后从该次运行的 Artifacts 下载 exe。

## 二、使用

双击 exe 打开界面,选择页签。

**母猪综合查询 / 猪只转移 / 母猪档案**(三个页签操作相同):

1. 添加 xlsx 文件或整个文件夹(含子文件夹,自动忽略 `~$` 临时文件)
2. 读取参数一般保持默认:
   - 母猪综合查询:跳过行数、标题行数为 `auto`,每个工作表单独识别(有无大标题行的文件可混在一起)
   - 猪只转移、母猪档案:一行标题(跳过 0 行、标题 1 行)
3. 选择导出格式和输出路径 → 开始处理

勾选「只读取合并, 不处理」时只把文件读进来合并导出,不做清洗。

**猪只转移**的单据信息从文件名中拆出,文件名需为:

```
单据编号_转移类型_转移方式_转出场-转入场_猪只类型_数量头_YYYYMMDD.xlsx
例: ZY20260105001_调拨_汽运_金沙一场-郭祥一场_后备母猪_120头_20260105.xlsx
```

只读取文件名符合这个规则的文件,其他文件跳过不读(日志里列出跳过了哪些)。
拆出 `单据编号 转移类型 转移方式 转出场 转入场 猪只类型 转移数量(整数) 转移时间(日期)`,
再按 `品种品系` 列判定 `品种`、`品系`。

**母猪档案**只读取文件名符合下面规则的文件:

```
母猪档案_猪场_生产阶段_N条_YYYYMMDD_HHMM.xlsx
例: 母猪档案_大庆一场_后备生产阶段_1990条_20261101_0805.xlsx
```

从文件名拆出 `档案猪场 档案阶段 档案条数(整数) 导出日期(日期) 导出时间("08:05")`
(加"档案"前缀,不覆盖表格里原有的 `猪场` 等列),再按 `品种品系` 列判定 `品种`、`品系`。
同时核对每个文件实际读到的行数与文件名中的条数,不一致时在日志中提醒(可能导出不完整)。

**来源列**:读取时只追加 `_file` 一列(文件完整路径,即 mintyr `import_xlsx(path_col = "_file")`
生成的列),不再生成 `excel_name`、`sheet_name`。

**读不了的文件**:勾选「跳过读不了的文件」(默认)时跳过并继续,日志「读取」部分逐个列出文件名、
所在文件夹和原因,结尾和完成弹窗也会提醒;不勾选时遇到就停止并列出全部原因。能识别的原因包括:
文件为空、文件不完整或已损坏、实际是网页(HTML)格式、可能设置了打开密码、被占用或没有权限、
文件不存在。Excel 打开文件时生成的 `~$` 临时文件会自动忽略。

**品种品系判定**:

- **编辑规则**:四张表格——品种规则、品系编码、中文名称、品系组合,以及「都不匹配时」的结果。
  双击单元格修改,可新增 / 删除 / 上移 / 下移;点「保存规则」后生效。可导入 / 导出规则文件(json)
  在多台电脑间共用;「恢复为内置默认」可随时回到原始规则。
- **测试**:输入任意写法,选「编辑中的规则」或「内置默认」判定;用编辑中的规则时,
  与内置结果不同的行显示为蓝色,并注明内置结果。可复制结果粘贴到 Excel,或导出 csv。

**规则的应用**:母猪综合查询、猪只转移、母猪档案三个页签都有「品种品系规则」选项,**默认为内置默认**
(与 R 版完全一致);选「自定义」则使用上面保存的规则。每次运行的日志会写明用的是哪套规则。

自定义规则影响:品种、品系的判定(母猪品种/品系、后裔品种/品系、公猪品系、猪只转移和母猪档案的品种/品系),
以及品系编码换算和血统计算。**后裔性质、与配公猪品种、托法 / 托法皮**是母猪综合查询特有的分类,
仍按内置逻辑(托法类用到的编码 3 / 8 的名称会跟随自定义编码表)。

| 格式 | 特点 | R 读取 |
|---|---|---|
| rds(默认) | R 原生,列类型(Date、factor、integer 等)原样保留,无需装包 | `readRDS()` |
| csv | 通用,Excel 可打开 | `data.table::fread()` |

参考(10 万行 × 61 列):rds 写入约 0.4 秒,文件 8 MB,R 读取约 0.4 秒。

界面设置会自动记住,下次打开不用重选。

**命令行**(适合定时任务 / 从 R 调用,日志写到输出文件同名 `.log`):

```
FPF数据处理.exe --cli D:\数据\综合选择查询 -o D:\结果\母猪综合.rds
FPF数据处理.exe --cli a.xlsx b.xlsx -o 母猪综合.rds --data-type 分娩
FPF数据处理.exe --cli D:\数据\猪只转移 --task transfer -o D:\结果\猪只转移.rds
FPF数据处理.exe --cli D:\数据\母猪档案 --task archive -o D:\结果\母猪档案.rds
FPF数据处理.exe --judge S332 托美 SYX32
FPF数据处理.exe --cli D:\数据\猪只转移 --task transfer --rules 品种品系规则.json -o 猪只转移.rds
```

`--rules` 指定自定义规则文件(界面中「导出…」得到;界面保存的规则在 `%USERPROFILE%\.fpf_breed_rules.json`),
不指定时使用内置默认规则。

R 中调用:`system2("FPF数据处理.exe", c("--cli", "D:/数据", "-o", "D:/结果/清洗.rds", "-f", "rds"))`

**运行信息**:风格仿照 R 的 cli 包,界面和命令行显示相同的内容:

```
── 读取 ──────────────────────────────────────────
ℹ 共 3 个文件, 标题: 自动识别
✔ [1/4] A场_2025.xlsx › Sheet1  1,484 行 × 39 列 (自动识别: 跳过 0 行, 标题 2 行) [67ms]
! 13 列中有无法识别为数值的内容, 已转为 NA:
  • 总产仔数: 61 个, 如 无
✔ 读取完成: 3,762 行 × 41 列 [228ms]
```

`ℹ` 信息、`✔` 完成、`!` 警告、`✖` 错误;方括号里是耗时;列名为绿色,文件名和取值为蓝色。
进行中的步骤先显示 `ℹ … ...`,完成后原地变成 `✔` 行。每次运行都会在输出文件旁边生成同名 `.log`
纯文本日志;出错时完整的错误信息也写在里面。Windows 旧版命令行窗口里 `✔ ℹ ✖` 会换成 `√ i ×`。

命令行运行时,exe 会把信息输出到启动它的命令行窗口。由于 exe 是窗口程序,命令提示符会先出现,
信息随后打印;想让窗口等它运行完再返回,可以用 `start /wait FPF数据处理.exe --cli ...`。

## 三、与 R 版的对应关系

| Python | R |
|---|---|
| `fpf/importer.py` → `import_xlsx()` | mintyr 0.2.1 `import_xlsx()` |
| `fpf/cleaning.py` → `clean_production_data()` | `综合选择查询数据处理_通用.R` |
| `fpf/transfer.py` → `process_transfer()` | 猪只转移: `get_path_info` + `tidyr::extract` + 品种品系判定 |
| `fpf/archive.py` → `process_archive()` | 母猪档案: 文件名拆分 + 品种品系判定 (已用等价的 R 流程逐格比对) |

已用同一批测试数据分别跑 R 和 Python 逐格对比:导入结果的列名、列类型、取值一致;
母猪综合查询 61 列、猪只转移 19 列的列名、类型、每个值(及因子水平)全部一致。
内置默认规则另用 3,205 个随机写法与 R 的全部判定函数(品种、品系、后裔、公猪、托法等 12 项)比对,全部一致。

猪只转移与 R 代码的差别:

1. R 代码 `get_path_info(_file, 5)` 取路径的第 5 段,只有文件恰好在第 5 层目录时才是文件名;
   本工具直接取文件名,文件放在哪一层都能拆分。
2. 文件名不符合规则的文件不读取(R 代码会读进来,单据信息为 NA)。
3. 不生成 `excel_name`、`sheet_name` 两列。
除此之外与 R 结果逐格一致。

与 R 版不同、**有意改进**的两处:

1. **日期列里混有文本(如 `--`)时**:readxl 会把这一列的日期变成序列号文本 `"45349"`,
   原 R 脚本随后 `as.Date()` 会报错 *character string is not in a standard unambiguous format*。
   本工具写成 `"2024-02-27"`,后续正常识别。
2. **字符型日期**:`2024/1/5`、`2024.01.05`、`2024年1月5日` 混写也能识别
   (R 的 `as.Date()` 只认首个值的格式)。

其余行为保持一致,包括:不在 `farm_order` 里的猪场会变成 NA(界面日志会提示是哪些猪场)。

## 四、以后增加新的功能页签

1. 在 `fpf/` 下新建模块,写一个 `函数(raw, verbose, log, **参数) -> DataFrame`
   (可参考 `fpf/transfer.py`)
2. 在 `fpf/pipeline.py` 的 `TASKS` 里登记:名称、函数、必需列、默认跳过行数 / 标题行数等
3. 在 `fpf/gui.py` 写一个参数区函数,加入 `TAB_SPECS`(可参考 `_transfer_params`)
4. 重新运行 `build_exe.bat`

品种品系判定函数在 `fpf/cleaning.py`:`classify_breed_label()`、`classify_line_label()`,
新功能直接调用即可;界面选择的规则由 `run_pipeline(rules=...)` 自动生效,无需额外处理。
内置规则在 `fpf/rules.py` 的 `DEFAULT_RULES`。

要改猪场排序/猪场类型:`fpf/cleaning.py` 顶部的 `FARM_ORDER`、`FARM_TYPE`。
要改品系编码:同文件 `LINE_CODE_MAP`、`LINE_TEXT_TO_CODE`。

## 文件结构

```
main.py              入口(命令行 + 启动界面)
fpf/gui.py           图形界面(各页签)
fpf/importer.py      xlsx 读取(mintyr import_xlsx 移植,calamine 引擎)
fpf/cleaning.py      母猪综合查询清洗 + 品种品系判定规则
fpf/transfer.py      猪只转移处理(含共用的品种品系判定 add_breed_line)
fpf/archive.py       母猪档案处理
fpf/rules.py         品种品系判定规则(内置默认 + 自定义规则的读写、校验)
fpf/breed.py         品种品系判定工具
fpf/pipeline.py      读取→处理→导出 流程, 任务登记(TASKS)
fpf/report.py        cli 风格运行信息
fpf/app_io.py        日志文件、错误显示
fpf/rds_writer.py    原生 .rds 写出
FPF.spec             PyInstaller 打包配置
build_exe.bat        Windows 一键打包
R读取示例.R          R 端读取示例
```
